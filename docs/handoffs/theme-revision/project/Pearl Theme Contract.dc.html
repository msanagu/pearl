PEARL DESIGN SYSTEM — THEME CONTRACT SPEC

One structure, four vibes.
A theme is colors + fonts + usage patterns — density, scale, and idiom are contract values too.

LAW 1 — AGNOSTIC MARKUP
Section markup references only contract variables — including its paddings, type sizes, and alignment. No literal colors, fonts, radii, durations, or spacing inside a template. If a theme can't fully reskin a section, the section is wrong — not the theme.
LAW 2 — SWAPPABLE SECTIONS
Pages are stacks of interchangeable sections. Layouts from retired style explorations stay in the library — the style was rejected, the structure wasn't. Any section slots into any page under any theme.
LAW 3 — VIBE IS DATA
Motion keyframes are global; themes override only parameter values. Same for whitespace and scale: every theme ships a space ramp and usage axes (density, display scale, accent budget, hover idiom) so switching themes switches temperament, not just paint.
§1 — The contract (vanilla-extract shape)
Extends the existing scheme in src/theme.css.ts — same createGlobalThemeContract + per-theme createTheme(vars, …) pattern, new axis groups only, no deviation. export const vars = createGlobalThemeContract({
  color: {
    ground: '',            // page behind everything; in exposed-grid themes it shows through the gaps
    surface: '', surfaceAlt: '', surfaceHover: '',
    hairline: '', hairlineStrong: '',
    ink: '', text: '', muted: '', faint: '',
    accent: { base: '', hover: '', alt: '', alt2: '', onAccent: '' },
    chrome: { bg: '', ink: '' },   // the one "loud cell" per view (CONTACT, primary CTA)
  },
  type: {
    display: { family: '', weight: '', transform: '', tracking: '', leading: '', fontStyle: '' },
    text:    { family: '' },
    label:   { family: '', tracking: '', wrap: '' },   // wrap: '/ % /' slash convention or '%'
    scale:   { hero: '', display: '', title: '', poster: '' },  // px ramp — themes differ WIDELY here
  },
  shape: { radiusControl: '', radiusCard: '', gridGap: '', hairlineWidth: '' },
  space: { hero: '', section: '', cell: '', row: '', stack: '' },  // whitespace ramp (shorthand paddings)
  usage: {                       // ── the vibe axes: structured, enumerable, machine-checkable ──
    density: '',        // 'airy' | 'comfortable' | 'compact' | 'poster-tight'
    displayScale: '',   // 'poster-xl' | 'editorial-lg' | 'product-md' | 'console-sm'
    accentBudget: '',   // 'one-chrome-cell' | 'one-small-loud-thing' | 'signals-only' | 'quiet-work-no-fills'
    hoverIdiom: '',     // 'lift-and-shadow' | 'tracking-stretch' | 'edge-rule' | 'border-signal'
    imagery: '',        // 'grayscale-plates' | 'warm-photography' | 'none-data-only' | 'soft-neutral'
    labelIdiom: '',     // 'mono-caps' | 'slash-caps' | 'mono-data-only' | 'quiet-mono'
    alignment: '',      // 'grid-locked' | 'centered-ceremonial' | 'left-utilitarian' | 'baseline-drift'
  },
  surfaceFx: {
    pearl: '', accentBar: '', noiseBlend: '', noiseOpacity: '', plateFilter: '',
  },
  luster: { angle: '', speed: '', size: '', blend: '', stops: '' },
  motion: { tempo: '', lift: '', easing: '', sheenSpeed: '', caretSpeed: '' },
});

// usage.* values are closed enums: a generator (human or LLM) reads them as hard constraints,
// e.g. usage.accentBudget='one-small-loud-thing' forbids a second accent fill in the same view.

§4 — Luster & motion: one keyframe set, four personalities
Keyframes are defined once, globally, and never per theme: luster (background-position 0% → 100% → 0%), sheen (a highlight band sweeping a CTA once per cycle), caret (steps(1) blink), plus the hover behaviors selected by usage.hoverIdiom. A theme expresses motion identity ONLY through parameter values — never by adding keyframes.
